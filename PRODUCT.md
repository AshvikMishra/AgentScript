# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Examiners and reviewers of a university compiler-design lab project. They open the shared link on
their own laptops after submission and explore unaided: they read the docs, load example programs in
the editor, compile them, look at each phase's output, and run tasks. The author (a solo student)
also demos it live.

## Product Purpose

AgentScript is a tiny language for AI-agent programs and a 10-stage compiler (lexer, parser,
semantic, IR+CFG, taint, approval, optimizer, scheduler, codegen, VM) that rejects unsafe programs
before any tool runs. Two headline guarantees: untrusted data (web_search, read_file) never reaches a
privileged tool (send_email, delete_file) without `sanitize` (E401), and every irreversible call is
dominated by a `confirm` approval branch (E501/E502). Success: a reviewer understands, unaided, that
the compiler really works and why each program is accepted or rejected.

## Positioning

Safety is proved statically by classic compiler analyses (forward data-flow taint, dominator-based
approval), not by runtime filtering or prompting. Every phase exposes its real artifact (tokens, AST,
symbols, IR, CFG, taint, approval, optimized IR, parallel rounds, bytecode).

## Operating Context

- Demo editor (`web/`): pick an example, edit, Compile (Ctrl+Enter), inspect the 10 phase tabs, pick
  a task, give JSON args, Approve/Deny `confirm()`, toggle Live tools, Run (Ctrl+Shift+Enter).
- Docs site (`docs/site/`): bundles README, PRD, implementation plan, how-it-works 00–11, demo
  script, viva notes, original PRD, and the 18 example programs, with search and Mermaid diagrams.
- Deployment: one Vercel project. Editor at `/`, docs site at `/docs`, FastAPI `/compile`, `/run`,
  `/examples` as a Python function. No API key is assumed; mock tools are the default.

## Capabilities and Constraints

- Stack is fixed: FastAPI backend, static HTML + vanilla JS front ends, CodeMirror 5 / Mermaid /
  marked / highlight.js from CDNs, no front-end build tooling. Docs site is generated by
  `docs/site/build.py` (stdlib only).
- Every existing editor feature, tab, shortcut, and docs page must be preserved.
- Compiler output shown anywhere must be real output, never hand-written.
- Error codes and locations come from `examples/manifest.json`.

## Evidence on Hand

Real compiler output via the API; 18 example programs with expected outcomes
(`examples/manifest.json`); 941 passing tests; deck `docs/presentation/AgentScript.pptx`; IEEE report
`docs/report/`. No users, testimonials, benchmarks, or adoption claims exist; none may be invented.

## Product Principles

1. Show the compiler working, don't describe it: real artifacts on screen.
2. The accept / reject / fix / run story must be obvious at a glance.
3. Specific to a compiler, never a generic SaaS template.
4. Nothing that exists today is lost.
